# Phase 4 — Stores & Corners Design (Store, CompanyStore)

- **Project:** Inventra (multi-tenant inventory management SaaS)
- **Date:** 2026-08-07
- **Status:** Design approved; pending implementation plan
- **Depends on:** Phase 1 (auth, permissions), Phase 2 (`OwnershipService`, `AuthUser.roleCode`), Phase 3 (catalog patterns: fetch-then-decide, soft-delete audit, ADMIN cross-tenant CRUD, creator/row-level scoping)

## 1. Goal & Scope

Build the **organizational layer** beneath the catalog: physical venues and the company corners inside them. Two feature modules:

- **Stores** — **global** physical venues (a department store / building). ADMIN-managed reference data, readable by everyone. Same shape as Categories.
- **Corners** (`CompanyStore`) — a **company-owned** presence inside a store: links `company` ↔ `store`, has **one manager** and **many staff**. Full CRUD plus manager/staff assignment.

**In scope:** two modules (service/controller/DTOs each), 9 new permissions + role grants, and one migration adding uniform soft-delete to `stores` and `company_stores`.

**Out of scope (Phase 5+):** product **placement** onto a corner's shelf (`CompanyStoreProduct` — with its stock fields `targetStockQuantity`/`sampleQuantity`/`reserved`/`current`), orders, inventory transactions. Those models already exist in `schema.prisma` and stay untouched.

**Grounding fact:** the seeded MANAGER role is described as *"Manages a company_store and its members."* The role was designed for this phase; the manager/staff authorization rules below lean into that.

## 2. Key Decisions

| # | Decision | Choice | Rationale |
|---|---|---|---|
| 1 | Phase scope | Stores + Corners; placement deferred to Phase 5 | Each is an independently testable slice; corners carry their own meaty concerns (manager/staff assignment). Placement sits cleanly on top later. |
| 2 | Store ownership | **Global**, ADMIN-managed reference data | `stores` has no company column; a venue is shared infrastructure (concession model: one building, many companies' corners). Writes ADMIN-only, reads open to all roles. Mirrors Categories. |
| 3 | Corner ownership | **Company-owned**, tenant-scoped via `OwnershipService` | `company_stores.company_id` is the owner column — `scopeToCompany(caller)` works unchanged. |
| 4 | Delete semantics | **Soft delete** for both `Store` and `CompanyStore` | Uniform with the catalog convention; adds `deletedAt` + `deletedByUserId` to both (one migration). Reads filter `deletedAt: null`. |
| 5 | Manager eligibility | Target must be **same company + ACTIVE + MANAGER role** | The MANAGER role *is* the corner manager by definition. Appointing a manager is an OWNER/ADMIN action — a manager cannot appoint the manager. |
| 6 | Staff assignment | OWNER/ADMIN (any corner) **and** MANAGER (only corners they manage) | Row-level scope beyond the binary permission — same shape as Phase 3's creator-scoped product delete, and exactly what the MANAGER role description promises. |
| 7 | Assignment API | **Sub-resource endpoints** (`/corners/:id/manager`, `/corners/:id/staff`) | Each action gets its own validation + permission and reads cleanly, vs. overloading `PATCH` / the Users module. |
| 8 | Assign permission | New **`corners.assign`** (distinct from `corners.update`) | Managing the roster is a distinct capability from editing corner metadata; lets MANAGER hold assign without holding update. |
| 9 | ADMIN + create | ADMIN has **full cross-tenant CRUD**; supplies `companyId` on corner create | Consistent with the Phase 3 final decision (`resolveCompanyForCreate`). |

## 3. Data Model Changes (one migration)

Add uniform soft-delete to the two tables that lack it. A nullable `deletedByUserId` FK to `users` with a **named** relation (User already relates to these models, so the delete relation needs its own name), set alongside `deletedAt`.

```prisma
model Store {
  // ... existing fields ...
  deletedAt       DateTime? @map("deleted_at") @db.Timestamptz(6)
  deletedByUserId String?   @map("deleted_by_user_id") @db.Uuid
  deletedByUser   User?     @relation("StoreDeletedBy", fields: [deletedByUserId], references: [id])
}
model CompanyStore {
  // ... existing fields ...
  deletedAt       DateTime? @map("deleted_at") @db.Timestamptz(6)
  deletedByUserId String?   @map("deleted_by_user_id") @db.Uuid
  deletedByUser   User?     @relation("CompanyStoreDeletedBy", fields: [deletedByUserId], references: [id])
}
model User {
  // ... existing fields ...
  deletedStores        Store[]        @relation("StoreDeletedBy")
  deletedCompanyStores CompanyStore[] @relation("CompanyStoreDeletedBy")
}
```

Migration (generated by `prisma migrate dev`) adds `deleted_at` + a nullable `deleted_by_user_id` (uuid, FK → `users(id)`) to `stores` and `company_stores`. All nullable → no backfill. No other schema changes: every column Corners needs (`companyId`, `storeId`, `managerUserId`, `User.companyStoreId`) already exists.

## 4. Permissions (seed additions)

**Nine new permission rows:** `stores.{create,read,update,delete}`, `corners.{create,read,update,delete}`, `corners.assign`. Total grows 20 → **29**.

**Role grants (`role_permissions`):**

| Permission | OWNER | MANAGER | STAFF | ADMIN |
|---|:---:|:---:|:---:|:---:|
| `stores.read` | ✓ | ✓ | ✓ | (wildcard) |
| `stores.create` / `stores.update` / `stores.delete` | — | — | — | (wildcard) |
| `corners.read` | ✓ | ✓ | ✓ | (wildcard) |
| `corners.create` / `corners.update` / `corners.delete` | ✓ | — | — | (wildcard) |
| `corners.assign` | ✓ | ✓ * | — | (wildcard) |

\* MANAGER holds `corners.assign`, but the service restricts it to **staff** changes on **corners they manage** (`corner.managerUserId === caller.id`). **Manager appointment** (`PUT /corners/:id/manager`) is OWNER/ADMIN-only regardless of `corners.assign` — see §7.

`stores.{create,update,delete}` are granted to **no role** (ADMIN wildcard only), same pattern as `categories.*` writes. `stores.read` and `corners.read` are granted to all company roles.

## 5. Module Structure

```
src/stores/   { stores.module, stores.service, stores.controller, dto/ }
src/corners/  { corners.module, corners.service, corners.controller, dto/ }
```

- `StoresModule` needs only `PrismaService` (global) — no ownership. Exports `StoresService` (exposes `findActive(id)` for Corners to reuse).
- `CornersModule` imports `AuthorizationModule` (`OwnershipService`), `StoresModule` (validate `storeId` at create — fetch-then-decide), and `UsersModule` (validate assignment targets via a `UsersService` lookup — fetch-then-decide).
- Both register in `AppModule.imports`. The global `JwtAuthGuard` + `PermissionsGuard` already protect every route.
- **`UsersService` addition:** `findActiveMember(userId, companyId)` → returns the user row **with its `role` included** (so eligibility can check the role code) or `null` (no throw); `CornersService` decides the 400. Keeps the lookup (and its scoping) in the owning service, the policy in the caller — the Phase 3 pattern.

## 6. Endpoints

**Stores** (`/stores`, global; `@RequirePermissions`):
- `GET /stores` (`stores.read`) — non-deleted list
- `GET /stores/:id` (`stores.read`)
- `POST /stores` (`stores.create`) — ADMIN
- `PATCH /stores/:id` (`stores.update`) — ADMIN
- `DELETE /stores/:id` (`stores.delete`) — ADMIN; soft delete

**Corners** (`/corners`, company-owned):
- `GET /corners` (`corners.read`) — caller's company corners (ADMIN: all)
- `GET /corners/:id` (`corners.read`) — scoped `findFirst` → cross-tenant id = 404
- `POST /corners` (`corners.create`) — OWNER; body `{ storeId, name?, description?, managerUserId?, companyId? }`; company via `resolveCompanyForCreate`; validate `storeId` (→ 400) and optional `managerUserId` (→ 400 if ineligible)
- `PATCH /corners/:id` (`corners.update`) — OWNER; edit `name`/`description` (not `companyId`/`storeId`)
- `DELETE /corners/:id` (`corners.delete`) — OWNER; soft delete
- `PUT /corners/:id/manager` (`corners.assign`, **OWNER/ADMIN only**) — body `{ userId }`; assign/replace manager; validate eligibility (§7); sets `managerUserId`
- `POST /corners/:id/staff` (`corners.assign`) — body `{ userId }`; add staff; sets `User.companyStoreId = corner.id`
- `DELETE /corners/:id/staff/:userId` (`corners.assign`) — remove staff; sets `User.companyStoreId = null`

`UpdateCornerDto = PartialType(OmitType(CreateCornerDto, ['companyId', 'storeId'] as const))` — a corner can't be moved to another company or venue via edit.

## 7. Tenant Scoping & Assignment Rules

**Corner scoping.** All corner ops resolve the corner through a scoped `findFirst`:
```ts
where: { id, ...this.ownership.scopeToCompany(caller), deletedAt: null }
```
A cross-tenant id returns `null` → **404** (no existence leak). ADMIN's `{}` scope spans all companies.

**Manager assignment** (`PUT /corners/:id/manager`):
1. Resolve the corner (scoped → 404 if not the caller's / absent).
2. **OWNER/ADMIN only** — a MANAGER may not appoint a manager, even though they hold `corners.assign` (403 otherwise). Enforced in the service via `caller.roleCode`.
3. Target user via `UsersService.findActiveMember(userId, corner.companyId)`; must be same company + `ACTIVE` + role `MANAGER`, else **400**.
4. Set `company_stores.managerUserId = userId`.

**Staff add/remove** (`POST` / `DELETE /corners/:id/staff`):
1. Resolve the corner (scoped → 404).
2. **Authorization:** OWNER/ADMIN → any corner in scope; **MANAGER → only if `corner.managerUserId === caller.id`**, else **403**.
3. (Add) Target user via `UsersService.findActiveMember(userId, corner.companyId)`; must be same company + `ACTIVE`, else **400**. Set `User.companyStoreId = corner.id`. (A user is staff of at most one corner — assigning them here reassigns them from any previous corner.)
4. (Remove) The target must currently be staff of *this* corner (`User.companyStoreId === corner.id`), else **404**; set `companyStoreId = null`.

`assertOwns` remains available; corners use scoped `findFirst` as the primary guard.

## 8. Error Handling

| Situation | Response |
|---|---|
| Cross-tenant / absent corner | 404 |
| Invalid `storeId` on corner create | 400 |
| Ineligible manager target (wrong company / not ACTIVE / not MANAGER) | 400 |
| Ineligible staff target (wrong company / not ACTIVE) | 400 |
| Remove a user who isn't staff of this corner | 404 |
| MANAGER appoints a manager, or touches a corner they don't manage | 403 |
| ADMIN creates a corner without `companyId` | 400 |
| Missing permission | 403 |
| Unauthenticated | 401 |

## 9. Testing

- **Unit specs (`StoresService`):** ADMIN-only writes are enforced by permission (guard-level, not here); service tests cover soft-delete stamping (`deletedAt` + `deletedByUserId`), `findActive` returning row-or-null, `findOne` throwing 404, reads filtering `deletedAt: null`.
- **Unit specs (`CornersService`):** tenant scoping (own vs cross-tenant vs ADMIN); `storeId` validation on create (400); manager eligibility (same company + ACTIVE + MANAGER, else 400); manager appointment blocked for MANAGER caller (403); staff add/remove eligibility (400) and the **MANAGER row-level rule** (own corner → ok; another's → 403); soft-delete stamping.
- **`UsersService` spec:** add `findActiveMember` cases (found / wrong company / not active → null).
- **e2e (`stores-corners.e2e-spec.ts`):** ADMIN creates a store → a company user cannot (403) → OWNER opens a corner in it → OWNER assigns a MANAGER (must be a MANAGER-role member) → that manager adds a STAFF to their corner (200) → a manager of a *different* corner is 403 adding staff → company 2 cannot fetch company 1's corner (404) → ADMIN reads across tenants and creates a corner via `companyId` (201).

## 10. Open Items

- **Phase 5 — Product placement** (`CompanyStoreProduct`): place catalog products onto a corner's shelf, with `targetStockQuantity` / `sampleQuantity` / `isActive`; `reserved`/`current` quantities are driven by later orders/inventory phases.
- `CompanyStore` has no unique `(companyId, storeId)` constraint — a company may run multiple corners in one venue. Intentional; not adding a constraint.
- The `prisma/models/*.prisma` dead files remain deletable in a future cleanup (independent of this phase).

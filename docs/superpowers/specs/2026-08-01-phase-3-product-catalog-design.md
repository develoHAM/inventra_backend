# Phase 3 — Product Catalog Design (Categories, Brands, Products)

- **Project:** Inventra (multi-tenant inventory management SaaS)
- **Date:** 2026-08-01
- **Status:** Implemented — Phase 3 complete (unit + e2e green)
- **Revision (2026-08-07):** Decision #6 changed during implementation — ADMIN now has **full cross-tenant CRUD** (not read-only). Sections §2/#6, §8, §9 below reflect the final behaviour.
- **Depends on:** Phase 1 (auth, permissions), Phase 2 (`OwnershipService`, `AuthUser.roleCode`)

## 1. Goal & Scope

Build the first feature domain — the **product catalog** — as the first real consumer of *both* halves of authorization: `@RequirePermissions` (can you?) + `OwnershipService` (is it yours?). Three resources:

- **Categories** — a **global** reference hierarchy (no owner); ADMIN-managed, readable by everyone.
- **Brands** — **company-owned** (`createdByCompanyId`); full CRUD, tenant-scoped.
- **Products** — **company-owned** (`companyId`); full CRUD, tenant-scoped; reference a company Brand + a global Category.

**In scope:** three feature modules (service/controller/DTOs each), the 12 new permissions + role grants, a small `Brand.deletedAt` migration, and an `OwnershipService` extension for the differing owner-column.

**Out of scope (later phases):** store placement (`CompanyStoreProduct`), orders, inventory, purchase reservations. All those models already exist in `schema.prisma` but stay untouched.

**Note on schema state:** the entire domain already exists in `prisma/schema.prisma` (the `prisma/models/*.prisma` files are dead commented-out leftovers). So Phase 3 needs **no** schema work beyond the one `Brand.deletedAt` column.

## 2. Key Decisions

| # | Decision | Choice | Rationale |
|---|---|---|---|
| 1 | Scope | Full catalog: Categories + Brands + Products | The coherent first feature slice; a Product needs both a Brand and a Category. |
| 2 | Category ownership | **Global** reference data (no tenant scope) | `categories` has no company column; it's a shared hierarchy. Writes ADMIN-only; reads open to all company roles. |
| 3 | Brand/Product ownership | **Company-owned**, tenant-scoped via `OwnershipService` | `brands.created_by_company_id` / `products.company_id`. |
| 4 | Owner-column mismatch | Extend `scopeToCompany(caller, field = 'companyId')` | Brand's owner column is `createdByCompanyId`, not `companyId`; one parameterized helper serves both. Backward-compatible. |
| 5 | Delete semantics | **Soft delete** for all three | Product/Category already have `deletedAt`; add `deletedAt` to Brand (small migration) for uniformity. Reads filter `deletedAt: null`. |
| 6 | ADMIN + create | ADMIN has **full cross-tenant CRUD**; names the target company via `companyId` on create | ADMIN administers the entire platform — reads *and* writes every company's catalog. On create it must supply `companyId` (→ 400 if omitted, via `resolveCompanyForCreate`); company users always act on their own company. |
| 7 | Product barcode | Globally unique → 409 on duplicate | `products.barcode` is `@unique` across all tenants. |
| 8 | MANAGER product delete | Granted, but restricted (in the service) to products they created | Row-level scope beyond the binary permission: OWNER deletes any company product, MANAGER only their own (`createdByUserId`). |
| 9 | Deletion audit | `deletedByUserId` FK on every soft-deleted table | Records *who* deleted each record; set together with `deletedAt`. A convention for all future soft-delete resources. |

## 3. Data Model Changes (one migration)

Two additions on the catalog tables:

1. **`Brand.deletedAt`** — Brand lacked a soft-delete column; add it for uniformity with Product/Category.
2. **`deletedByUserId` on Product, Brand, Category** — a nullable FK to `users` recording *who* deleted the row, with a **named** relation (User already relates to Product/Brand via `createdByUser`, so the delete relation needs its own name). Set alongside `deletedAt`.

```prisma
model Brand {
  // ... existing fields ...
  deletedAt       DateTime? @map("deleted_at") @db.Timestamptz(6)
  deletedByUserId String?   @map("deleted_by_user_id") @db.Uuid
  deletedByUser   User?     @relation("BrandDeletedBy", fields: [deletedByUserId], references: [id])
}
model Product {
  // ... existing fields ...
  deletedByUserId String? @map("deleted_by_user_id") @db.Uuid
  deletedByUser   User?   @relation("ProductDeletedBy", fields: [deletedByUserId], references: [id])
}
model Category {
  // ... existing fields ...
  deletedByUserId String? @map("deleted_by_user_id") @db.Uuid
  deletedByUser   User?   @relation("CategoryDeletedBy", fields: [deletedByUserId], references: [id])
}
model User {
  // ... existing fields ...
  deletedProducts   Product[]  @relation("ProductDeletedBy")
  deletedBrands     Brand[]    @relation("BrandDeletedBy")
  deletedCategories Category[] @relation("CategoryDeletedBy")
}
```

Migration (generated by `prisma migrate dev` from the model edits) adds `brands.deleted_at` plus a nullable `deleted_by_user_id` (uuid, FK → `users(id)`) on `brands`, `products`, `categories`. All nullable → no backfill on the existing tables.

## 4. Permissions (seed additions)

**Twelve new permission rows:** `products.{create,read,update,delete}`, `brands.{create,read,update,delete}`, `categories.{create,read,update,delete}`.

**Role grants (`role_permissions`):**

| Permission | OWNER | MANAGER | STAFF | ADMIN |
|---|:---:|:---:|:---:|:---:|
| `products.read` / `brands.read` / `categories.read` | ✓ | ✓ | ✓ | (wildcard) |
| `products.create` / `brands.create` | ✓ | ✓ | — | (wildcard) |
| `products.update` / `brands.update` | ✓ | ✓ | — | (wildcard) |
| `products.delete` | ✓ | ✓ * | — | (wildcard) |
| `brands.delete` | ✓ | — | — | (wildcard) |
| `categories.create` / `categories.update` / `categories.delete` | — | — | — | (wildcard) |

\* MANAGER holds `products.delete`, but the service restricts it to products the manager created (`createdByUserId === caller.id`) — see §8a.

`categories.{create,update,delete}` are granted to **no role**, so only the ADMIN wildcard reaches them (same pattern as `companies.approve`). `categories.read` **is** granted to all company roles — required so a company can list categories when creating a product.

## 5. Module Structure

```
src/categories/  { categories.module, categories.service, categories.controller, dto/ }
src/brands/      { brands.module, brands.service, brands.controller, dto/ }
src/products/    { products.module, products.service, products.controller, dto/ }
```
- `BrandsModule` and `ProductsModule` import `AuthorizationModule` (inject `OwnershipService`).
- `CategoriesModule` needs only `PrismaService` (global) — no ownership.
- All three register in `AppModule.imports`. The global `JwtAuthGuard` + `PermissionsGuard` already protect every route.

## 6. Endpoints

**Categories** (global; `@RequirePermissions`):
- `GET /categories` (`categories.read`) — non-deleted list
- `GET /categories/:id` (`categories.read`)
- `POST /categories` (`categories.create`) — ADMIN
- `PATCH /categories/:id` (`categories.update`) — ADMIN
- `DELETE /categories/:id` (`categories.delete`) — ADMIN; soft delete

**Brands** (company-owned):
- `GET /brands` (`brands.read`) — caller's company brands
- `GET /brands/:id` (`brands.read`)
- `POST /brands` (`brands.create`) — `createdByCompanyId = caller.companyId`
- `PATCH /brands/:id` (`brands.update`)
- `DELETE /brands/:id` (`brands.delete`) — soft delete

**Products** (company-owned):
- `GET /products` (`products.read`) — caller's company products
- `GET /products/:id` (`products.read`)
- `POST /products` (`products.create`)
- `PATCH /products/:id` (`products.update`)
- `DELETE /products/:id` (`products.delete`) — soft delete

## 7. Tenant Scoping (`OwnershipService` extension)

Extend `scopeToCompany` with an optional owner-column name (default preserves Phase 2 behaviour):
```ts
scopeToCompany(caller: AuthUser, field = 'companyId'): Record<string, string> {
  if (caller.roleCode === 'ADMIN') return {};
  if (!caller.companyId) throw new ForbiddenException();
  return { [field]: caller.companyId };
}
```
- **Products:** `where: { ...scopeToCompany(caller), deletedAt: null }`
- **Brands:** `where: { ...scopeToCompany(caller, 'createdByCompanyId'), deletedAt: null }`

Every single-record op (`GET/:id`, `PATCH`, `DELETE`) uses a scoped `findFirst`, so a cross-tenant id returns `null` → **404** (no existence leak). ADMIN's `{}` scope reads across all companies. `assertOwns` remains available for future by-global-id lookups.

## 8. Product-Creation Validations (`POST /products`)

1. **Company resolved:** via `resolveCompanyForCreate(caller, dto.companyId)` — a company user gets their own `companyId`; ADMIN must supply `dto.companyId` (→ **400** if missing). Set `createdByUserId = caller.id`.
2. **Brand must be the caller's:** `findFirst({ where: { id: brandId, createdByCompanyId: caller.companyId, deletedAt: null } })`; not found → **400** (can't reference another company's brand).
3. **Category must exist:** `findUnique` on `categoryId`, non-deleted; else **400**.
4. **Barcode unique:** pre-check `products.barcode`; duplicate → **409**.

`POST /brands` resolves the owner company the same way: `createdByCompanyId = caller.companyId` for a company user, or `dto.companyId` for ADMIN (→ 400 if ADMIN omits it).

## 8a. Deletion Rules

All three resources **soft-delete**: set `deletedAt = now()` **and** `deletedByUserId = caller.id`, and every read filters `deletedAt: null`.

**Creator-scoped MANAGER delete (Products).** `DELETE /products/:id` is reachable by OWNER and MANAGER (both hold `products.delete`). After the company-scoped lookup:
- **OWNER** (or ADMIN) → may delete any of the company's products.
- **MANAGER** → may delete only products where `createdByUserId === caller.id`; otherwise **403** (`ForbiddenException` — the product is visible to them, they just may not delete another's).

The service distinguishes roles via `caller.roleCode`. Brand and Category delete have no creator restriction (OWNER-only / ADMIN-only respectively).

## 9. Error Handling

| Situation | Response |
|---|---|
| Cross-tenant record (brand/product) | 404 |
| ADMIN creates without naming a company (`companyId`) | 400 |
| MANAGER deletes a product they didn't create | 403 |
| Duplicate barcode | 409 |
| Invalid brand reference (not yours / missing) | 400 |
| Invalid/missing category | 400 |
| Missing permission | 403 |
| Unauthenticated | 401 |

# Phase 1 — Authentication & Authorization Implementation Plan

> **Execution note:** This project is built *interactively* — the developer types each piece while pairing with an AI tutor. Tasks are ordered and independently testable; we build and commit one at a time, with teaching. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add local email+password auth (access+refresh JWT), a role/permission authorization layer with per-user grant/deny overrides, company self-signup, and a platform super-admin.

**Architecture:** Two global guards run per request — `JwtAuthGuard` (authN: verify token, load user fresh) then `PermissionsGuard` (authZ: role + GRANTs − DENYs, ADMIN wildcard). Auth, authorization, and user-lifecycle live in three modules. Refresh tokens are hashed, stored, and rotated.

**Tech Stack:** NestJS 11, Prisma 7 (`@prisma/adapter-pg`), `@nestjs/jwt`, `argon2`, `class-validator`/`class-transformer`, Zod (config).

**Design source:** [`docs/superpowers/specs/2026-07-13-phase-1-auth-design.md`](../specs/2026-07-13-phase-1-auth-design.md)

## Global Constraints

- Permissions resolved **fresh per request** (no permissions baked into JWTs).
- Two separate JWT secrets (`JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`).
- Access token 15m, refresh token 7d; refresh tokens stored **hashed**, rotated on use.
- Passwords hashed with **argon2id**; raw passwords never stored or logged.
- All env additions validated in `src/config/env.schema.ts` (fail-fast on boot).
- Guards register via `APP_GUARD`; routes are **auth-required by default**, opt out with `@Public()`.
- 401 = unauthenticated; 403 = authenticated-but-forbidden.
- No deferrable FKs; `users.company_id` is nullable (platform admin has no company).

## Task 4 — `TokenService` (sign/verify/rotate)

**Files:**
- Create: `src/auth/token.service.ts`
- Test: `src/auth/token.service.spec.ts`

**Interfaces (Produces):**
- `signAccess(userId): Promise<string>` — payload `{ sub, type: 'access' }`, access secret, 15m.
- `signRefresh(userId): Promise<{ token: string; jti: string }>` — payload `{ sub, type: 'refresh', jti }`, refresh secret, 7d.
- `verifyAccess(token): Promise<{ sub: string }>` — rejects if `type !== 'access'`.
- `verifyRefresh(token): Promise<{ sub: string; jti: string }>` — rejects if `type !== 'refresh'`.
- `hashToken(token): string` — SHA-256 hex, for storage/lookup.

- [ ] Tests: access token verifies and carries `sub`; a refresh token rejected by `verifyAccess` (type mismatch); expired token rejected; `hashToken` is stable.
- [ ] Run → fails.
- [ ] Implement using `JwtService` (injected, configured per-call with the right secret/expiry from `ConfigService`) + `crypto` for `hashToken`.
- [ ] Run → passes.
- [ ] Commit: `feat(auth): add TokenService (sign/verify/rotate helpers)`
